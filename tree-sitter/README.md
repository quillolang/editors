# tree-sitter-quillo

A [tree-sitter](https://tree-sitter.github.io) grammar for Quillo's `.qwe` files, with the
queries editors read: highlighting, injections, locals, folds and indents. The Zed, Neovim,
Helix and Emacs support in this repository is built on it.

A `.qwer` file is Rust (with a `//! [dependencies]` header in TOML), so editors give it
[tree-sitter-rust](https://github.com/tree-sitter/tree-sitter-rust): there is no grammar of its own.

## What it reads as quillo does

The grammar follows quillo's own parser (`src/parser.rs`, `src/lexer.rs`), with
[`src/scanner.c`](src/scanner.c) for what rules cannot say alone:

- **A newline ends a statement** only where one can end, and not when the next line goes on
  with it: `|`, `||`, `&&`, `?`, `??`, `:`, `.` (not `..`), `else`, `*`, `%`, `==`, `!=`, and
  `- x` or `+ x` with a space. `-y` against its number starts a statement. Inside `(...)` and
  `[...]` no newline counts; in a map `{ ... }` one separates entries, as a comma does.
- **A route's path** is read before comments, so `route GET /*rest` is a path.
- **Markup text** runs to the next `<`, `{` or `}`. `//` starts a comment there only at the
  start of a line, so `<p>a // b</p>` is text. `br`, `img`, `input` and the other void
  elements take no end tag.
- **`r?`** passes an error on when the `?` is written against what it follows; `a ? b : c`,
  with a space, is the ternary.
- **`client`, `import`, `type`, `site`, `state`, `style`, `server`, `routes`, `service`,
  `mount`, `private` and `public`** start their statements and are names everywhere else:
  `client = 1`, `{ state, type }`, `(type: str) => ...`.
- **`mcp`**, the tag of a tool, is one only right after `fn`, `view` or `component` with a
  name after it on its line (`fn mcp total()`, `server fn mcp add_note()`), or after `service`
  with a name or a path (`service mcp /billing = "billing.qwe"`); the scanner decides, as
  quillo's highlighter does. `fn mcp(x)`, the second `mcp` of `fn mcp mcp()`,
  `service mcp = "mcp.qwe"`, `service mcp /* note */ = ...` and `mcp` anywhere else are names.
- `{}` and `{ x }` are maps, as quillo reads them; `{ x = 1 }` is a block.

## Queries

[`queries/`](queries) uses Neovim's capture names. [`scripts/queries.js`](scripts/queries.js)
writes each editor's copy from it, in that editor's names and order: `../neovim/queries/quillo`,
`../helix/queries/quillo` (where the first pattern that matches wins, so the order is turned
around) and `../zed/languages/quillo`. Change the queries here, then run `npm run queries`.

Injected: CSS in `` css`...` `` (so in `` style css`...` ``) and in `<style>`; SQL in
`` sql`...` `` and in the string or template `db.exec`, `db.one` and `db.query` are given first;
JavaScript in `<script>`. A template's text around its `${...}` is one document to the language.

## Tests

```sh
npm ci
npm test
```

- `test/corpus/`: the trees of each construct, and inputs that must be errors.
- `test/highlight/`: what each part of a program is highlighted as.
- `test/corpus-files.js`: every `.qwe` file of the Quillo repositories beside this one
  (`quillo-app1`, `quillo-examples`, `quillo-components`, `quillo-website`, `quillo-starter`,
  or the folders in `QUILLO_CORPUS`) parses with no error: 2,800 files on 2026-11-02.
- `test/queries.js`: every query compiles, the editors' copies too, the injections find their
  CSS, SQL and JavaScript, the builtins are the TextMate grammar's, and the copies are up to date.

`src/parser.c` is generated by `tree-sitter generate` and committed, as editors build the
parser from the repository without running it.
